### F8 finding

The startup text in the DLL advertises:

`[F9 or Ctrl+P] = export | [F8] = re-scan`

However, the compiled symbol/string inventory contains:
- `get_f9Key`
- `get_pKey`
- Ctrl key accessors
- `get_wasPressedThisFrame`

and does **not** contain `get_f8Key` or a dedicated rescan method.

Conclusion: F8 is advertised but not implemented in the 5.1 binary.

## Upstream mismatch

The public upstream source currently visible on `main` identifies the plugin as 5.0.0 and lacks several pieces that exist in the 5.1 DLL, including configuration/row-limit and incremental-writer functionality.

Therefore, the public 5.0 source must not be treated as an exact 5.1 baseline.

## Historical F8 reference

An older upstream commit (`72463987fb2082ddfc10655e66590a88568e21b7`) contains a working F8 implementation that called `ScanUIDocuments()`. We can use that as a behavioral reference, but not copy the old architecture wholesale.
